# Meet-up Orders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Customers can choose a meet-up instead of delivery. They pick one of the owner's places, a day the place is open, and a 30-minute time inside its hours.

**Architecture:**
- **Shop settings:** the settings document gains meet-up places, each with seven weekday hour rows, validated like towns and delivery hours.
- **Orders:** an order gains a fulfilment type and a meet-up snapshot (place name, note, time). One module, `orders/meetups.py`, decides the allowed days and times on the server. `lib/orderCheckout.ts` mirrors those rules for the checkout.
- **Display:** every place that shows an order uses one fulfilment line.

**Tech Stack:** Django 5.2 + DRF, React 19 + TS, node regression scripts, Playwright scratch check.

**Spec:** `docs/superpowers/specs/2026-11-15-meetups-design.md`

## Global Constraints

**Places**
- Name: 1–80 characters, unique ignoring case. Note: 0–160 characters. `<` and `>` are rejected in both. At most 10 places.
- Every place has 7 hour rows (weekday 0 = Monday). An open row needs `opens < closes`, and a meet-up window must be ≥ 30 minutes long.
- A place that is on needs at least one open day.
- A settings PUT without `meetup_places` keeps the stored places.
- Public settings carry active places only: `{id, name, note, hours}`.

**Time picks**
- Times: from `opens`, every 30 minutes, up to and including `closes − 30 min`.
- Today (Manila): only times ≥ now + 60 minutes.
- A day is offered only when it has ≥ 1 time. A place with no offerable day isn't listed.
- Days otherwise follow lead days, the cutoff, days off and the 30-day limit. Delivery's `show_hours` doesn't apply; the place's own hours do.

**Orders**
- `fulfilment` is `delivery` (default) or `meetup`.
- A meet-up has `delivery_fee` 0.00, `town_name = ''`, `address = ''`, a snapshot of the place's name and note, and `meetup_time`.

**Exact messages**
- Settings:
  - `meetup_places.N.hours.D.closes`: "Leave at least 30 minutes between opening and closing."
  - `meetup_places.N.hours`: "Open this place on at least one day, or switch it off."
  - Duplicate name: "This place is already in the list."
- Orders:
  - `meetup_place`: "Pick where to meet."
  - `delivery_date`: "We don't meet there on <Mon D>. Pick another day."
  - `meetup_time` outside the window or off the grid: "Pick a time between <first> and <last>."
  - `meetup_time` too soon today: "Pick a time at least an hour from now."
  - Checkout with neither delivery nor meet-up: "We're not taking orders for delivery or meet-ups right now. Message us on Messenger."

**Display**
- Fulfilment line: "Meet-up: <place>, <Ddd, Mon D>, <h:mm AM/PM>" or "Delivery: <Ddd, Mon D>, <town>".
- Sale notes: "Online order <number>, <name>, meet-up at <place>, <Ddd, Mon D>, <h:mm AM/PM>".

**Quality**
- TDD. SQLite and `python scripts/test_postgres.py`. Browser checks at 375 and 1440 in Chromium and WebKit, axe 0, CSP 0.
- Do not deploy.

## Review Focus

1. **A place is renamed, switched off or removed while an order for it waits.** The order still shows the snapshot name and note, and Confirm works with `meetup_place` set to null. Tested in Task 2.
2. **Ordering for today near closing time.** Times are cut by the 60-minute rule, the day disappears when no time is left, and the server enforces the same on `delivery_date` and `meetup_time`. Tested in Tasks 2 and 3.
3. **An old settings tab saving without `meetup_places`.** The places are kept. Tested in Task 1.
4. **Switching Delivery ↔ Meet-up in the form.** Input in each mode is kept, errors for hidden fields are cleared, and delivery orders behave exactly as before (the existing order tests stay green). Tested in Task 5 (browser).
5. **A place switched off after the customer loaded the shop.** The server answers "Pick where to meet." on `meetup_place`. Tested in Task 2.
