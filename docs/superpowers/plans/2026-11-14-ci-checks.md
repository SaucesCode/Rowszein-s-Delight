# Automatic Checks and PostgreSQL Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every push and pull request runs the backend, PostgreSQL, frontend and dependency-audit checks, and the 17 PostgreSQL-only tests run again.

**Architecture:**
- **The runner:** one Python script, `scripts/test_postgres.py`, starts a throwaway `postgres:17-alpine` Docker container on a random loopback port with a generated name and password. It runs Django's test runner from code, so the guard in `backend/test_settings.py` stays intact, and always removes the container.
- **The workflow:** a GitHub Actions file runs four independent jobs on Ubuntu, using the same commands we run locally.

**Tech Stack:** Python 3.12, Django 5.2 test runner, Docker, GitHub Actions, Node 24.

**Spec:** `docs/superpowers/specs/2026-11-14-ci-checks-design.md`

## Global Constraints

**Versions**
- Python 3.12 and Node 24.
- Actions are pinned to `actions/checkout@v4`, `actions/setup-python@v5` and `actions/setup-node@v4`.

**Throwaway database**
- Image `postgres:17-alpine`.
- Container name `rowszein-test-<hex>`.
- Published only on `127.0.0.1:<port>`, with the port in 1024–65535.
- Database name matches `rowszein_phase1a_[0-9a-f]{32}`; the password is random.

**The test-settings guard**
- `backend/backend/test_settings.py` is not loosened. `manage.py test` with `ROWSZEIN_TEST_POSTGRES=1` must still be refused.

**Isolation**
- No step reads `backend/.env` or connects to any database the run didn't create.
- The container is removed on success, failure and Ctrl+C.

**Workflow**
- Triggers on `push` and `pull_request`.
- `permissions: contents: read`.
- `concurrency` cancels older runs on the same ref.

**Repository rules**
- Script line endings follow `.gitattributes`.
- Nothing is pushed or deployed. The workflow proves itself only when the owner pushes.

## Review Focus

1. **Docker missing or not running.** Expect a one-line "Docker isn't running…" message, a non-zero exit, and no hang. Tested in Task 1.
2. **Tests fail, or the run is interrupted.** The container must still be removed (`docker ps -a` shows no `rowszein-test-` container afterwards). Tested in Task 1.
3. **PostgreSQL is slow to start.** The readiness wait retries for up to 60 s, then fails with a clear message rather than running tests against a closed port. Tested in Task 1 (unit test of the wait loop with a fake probe).
4. **Test labels passed to the runner** (`python scripts/test_postgres.py sales`). Only those tests run. Tested in Task 1.
5. **The guard still refuses the unsafe path.** `ROWSZEIN_TEST_POSTGRES=1 manage.py test` raises the guard error. Tested in Task 1.

### Task 1: The disposable PostgreSQL runner

**Files:**
- Create: `scripts/test_postgres.py`
- Test: `scripts/test_test_postgres.py` (stdlib `unittest`, runs with `python scripts/test_test_postgres.py`)

**Interfaces:**
- **Produces, in `scripts/test_postgres.py`:**
  - `new_identity() -> tuple[str, str]`, which returns `(db_name, password)`.
  - `free_port() -> int`.
  - `test_environment(db_name: str, port: int, password: str) -> dict[str, str]`. It returns `os.environ` plus `ROWSZEIN_TEST_POSTGRES=1`, `ROWSZEIN_TEST_DB_NAME`, `ROWSZEIN_TEST_DB_PORT`, `ROWSZEIN_TEST_DB_PASSWORD` and `DJANGO_SETTINGS_MODULE=backend.test_settings`.
  - `wait_until_ready(probe: Callable[[], bool], timeout: float = 60, interval: float = 1) -> None`. It raises `RuntimeError("PostgreSQL didn't start within 60 seconds.")` on timeout.
  - `main(argv: list[str]) -> int`. Its arguments are the test labels.
- **Produces the command line:** `python scripts/test_postgres.py [labels...]`. The exit code is the test result, and 2 means Docker is unavailable.
- **The Python used for the tests:** `backend/.venv/Scripts/python.exe` if it exists (Windows), else `backend/.venv/bin/python`, else `sys.executable` (CI).

- [ ] **Step 1: Write the failing unit tests** in `scripts/test_test_postgres.py`.
  - `test_identity_matches_the_guard`: the name matches `^rowszein_phase1a_[0-9a-f]{32}$`, two calls give different names and passwords, and the password is at least 24 characters.
  - `test_free_port_is_in_range`: `1024 <= free_port() <= 65535`.
  - `test_environment_opts_in_and_names_the_database`: the four `ROWSZEIN_*` keys and `DJANGO_SETTINGS_MODULE` have exactly those values, and the port is a string.
  - `test_wait_gives_up_with_a_clear_message`: a probe that is always False, with `timeout=0.2, interval=0.05`, raises `RuntimeError` whose message contains "didn't start".
  - `test_wait_returns_once_ready`: a probe that is False twice and then True returns, and it was called 3 times.
  - `test_unsafe_path_is_still_refused`: run `backend` Python with `manage.py test --settings=backend.test_settings` and `ROWSZEIN_TEST_POSTGRES=1` in the environment. The exit is non-zero and stderr contains "no verified disposable ownership".
  - `test_missing_docker_exits_2`: run `main([])` with `PATH` emptied for the subprocess lookup (patch `shutil.which` to return None). It returns 2.

- [ ] **Step 2: Run** `python scripts/test_test_postgres.py`.
  Expected: an ImportError or FAIL, because the module is missing.

- [ ] **Step 3: Implement `scripts/test_postgres.py`.**
  - `docker run -d --rm --name rowszein-test-<hex> -e POSTGRES_PASSWORD=… -e POSTGRES_DB=… -p 127.0.0.1:<port>:5432 postgres:17-alpine`.
  - The probe runs `docker exec <name> pg_isready -U postgres -d <db>`. After the probe succeeds, also try a TCP connect to `127.0.0.1:<port>`.
  - Run the tests as a subprocess in `backend/` with `test_environment(...)`. The program is passed with `-c`:

    ```python
    import sys, django
    from django.conf import settings
    django.setup()
    from django.test.utils import get_runner
    sys.exit(bool(get_runner(settings)(verbosity=2).run_tests(sys.argv[1:])))
    ```

    Pass the labels after `-c <program>`, so `sys.argv` never contains `test`.
  - Stop the container with `docker stop` in a `finally` block that also covers `KeyboardInterrupt`.
  - Docker missing (`shutil.which("docker")` is None) or `docker info` failing prints "Docker isn't running. Start Docker Desktop, then try again." and returns 2.

- [ ] **Step 4: Run** `python scripts/test_test_postgres.py`.
  Expected: OK, 7 tests.

- [ ] **Step 5: Run the real thing, and check the clean-up.**
  - Run `python scripts/test_postgres.py sales`.
    Expected: a test summary line with `skipped=0` for the PostgreSQL-only tests. Record the pass/fail counts in the ledger.
  - Then run `docker ps -a --filter name=rowszein-test- --format "{{.Names}}"`.
    Expected: empty output.

- [ ] **Step 6: Commit**
  `git commit -m "feat(ci): disposable PostgreSQL test runner"`

### Task 3: GitHub Actions workflow

**Files:**
- Create: `.github/workflows/checks.yml`

**Interfaces:**
- **Consumes:** `scripts/test_postgres.py` (Task 1).
- **Produces:** four jobs, named `backend`, `backend-postgres`, `frontend` and `audit`.

- [ ] **Step 1: Write the workflow.** Every job runs on `ubuntu-latest` with `timeout-minutes: 15`, and `defaults.run.shell: bash`.
  - **`backend`**
    - checkout, then setup-python `3.12` with `cache: pip` and `cache-dependency-path: backend/requirements.txt`;
    - `pip install -r backend/requirements.txt`;
    - then, in `backend/`: `python manage.py check --settings=backend.test_settings`, `python manage.py makemigrations --check --dry-run --settings=backend.test_settings`, and `python manage.py test --settings=backend.test_settings`.
  - **`backend-postgres`:** the same setup and pip install, then `python scripts/test_postgres.py`.
  - **`frontend`**
    - setup-node `24` with `cache: npm` and `cache-dependency-path: frontend/package-lock.json`;
    - in `frontend/`: `npm ci`, `npx tsc -b`, `npx eslint .`, `npx vite build`;
    - then from the repository root: `for f in tests/regression/*.mjs; do echo "::group::$f"; node "$f" || { echo "::error::$f failed"; exit 1; }; echo "::endgroup::"; done`.
  - **`audit`:** setup-python and setup-node, then `pip install pip-audit && pip-audit -r backend/requirements.txt`, then `npm audit --audit-level=high` in `frontend/`.

- [ ] **Step 2: Check that the YAML parses.** Run `node -e "require('js-yaml')"` from `frontend/` if available; otherwise use `python -c "import yaml"` after `pip install pyyaml` into a scratch venv, not the backend venv. Load the file and assert that the four job keys and both triggers are present.
  Expected: it parses, and the keys are present.

- [ ] **Step 3: Run each job's commands locally** in Git Bash, in the same order, using `backend/.venv` Python and Node 24.
  - Expected: each one exits 0.
  - Run `pip-audit` from a scratch venv. Ledger any advisories it reports. They are findings to show the owner, not things to silence.

- [ ] **Step 4: Commit**
  `git commit -m "ci: checks on every push and pull request"`
