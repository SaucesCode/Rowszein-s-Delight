## V2 — SQLite trigger DDL placeholder conversion (corrected with explicit approval)

The original 0003 uses schema_editor.execute(sql), whose default empty parameter tuple makes Django's SQLite adapter rewrite literal `%s` to `?`, even within SQL strings. Stored accounts_throttle_insert/update SQL therefore uses strftime('?', timestamp), invalidating valid epoch-microsecond events. Confirmed by real stored-trigger inspection and direct debit regression in `20261110-144141-sqlite-diagnostic-b5748ee5`. The HTTP layer correctly fails closed with 503; authentication is unavailable, never unthrottled. Proposed correction is params=None for the SQLite trigger execution only; no role, precision, quota, model or revocation policy change. Exact patch and proposed SHA are recorded. Original migration remains unchanged pending the owner's explicit revised-hash decision; no guard or hash check is disabled.

Resolution after the preserved checkpoint above: the owner explicitly replied “Approve corrected hash and fresh disposable tests.” Applied exactly the prepared line, producing approved SHA 3b8156d1eee07b1e73affde5898d47888b237e579913c785e99a6652eabe9e2c. Original static evidence/manifests remain intact. New targets only: corrected SQLite full suite has 27 schema checks, 91/94 security tests passing with three PostgreSQL-only skips, 103/120 business passes with 17 PostgreSQL-only skips, all 21 RBAC checks, and 33 real-browser checks. Corrected PostgreSQL full confirmation also passes. The narrowed approval verifier accepts only the original 0002 and this exact one-line 0003 transformation; five database-free tests reject extra edits, changed 0002, altered approval and missing owner record.

Additional setup evidence: the first SQLite browser attempt lacked sandbox loopback access and timed out before checks; the next observed a real 201 after a fixed probe delay had already expired. Kept both failed attempts. Used loopback permissions and response-completion observation without changing application timeouts or assertions; the fresh final SQLite run passes all 33 checks. The first approval-verifier unit setup used the sandbox's unwritable default temporary directory; moved its bounded temporary fixtures into the verified workspace and all five tests pass. These are harness/setup corrections, not authentication bypasses.
